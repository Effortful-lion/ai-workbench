# 手动操作指南

> 如果你不想用 `make`，或者 make 不适用（比如只想跑单个服务、或者想用 Nest CLI 的原始命令），这份文档把每一步拆开来讲。

---

## 0. 环境前置

| 工具 | 版本要求 | 验证命令 |
|---|---|---|
| Node.js | ≥ 20 | `node -v` → v20+ 或 v22+ |
| pnpm | ≥ 11 | `pnpm -v`（packageManager 已锁 `11.22.0`） |
| sqlite3 CLI | 可选 | `sqlite3 --version`（DBeaver / 其他 GUI 也能连） |

## 1. 首次初始化（从零到能跑起来）

```bash
# ① 进项目根目录
cd /Users/lion/workspace/gocode/ai-workbench

# ② 装依赖（pnpm workspace 会一起拉 server / web / shared）
pnpm install

# ③ 建目录
mkdir -p data

# ④ 推 schema 到 SQLite（首次运行自动建 24 张表，之后启动 server 时 Auth 模块会自动补 admin 种子）
pnpm --filter @aiwb/server db:push
```

完成这四步，`data/workbench.db` 就建好了，表齐了，admin 用户等 server 启动后自动出现。

## 2. 启动

项目有两个服务，**可以分着跑也可以一起跑**。

### 方式 A：同时启动（最方便，开发首选）

```bash
pnpm dev
```

这一条等价于 `pnpm -r --parallel run dev` —— server 和 web 各占一个终端输出位置（pnpm 用 `[pnpm]` 前缀区分）。Ctrl+C 同时停两个。

### 方式 B：分着启动（想单独看某一个的日志）

开两个终端窗口：

```bash
# 终端 ①：Server（NestJS watch 模式，改代码自动重启）
cd /Users/lion/workspace/gocode/ai-workbench
pnpm --filter @aiwb/server dev

# 终端 ②：Web（Vite dev + HMR）
cd /Users/lion/workspace/gocode/ai-workbench
pnpm --filter @aiwb/web dev
```

### 方式 C：生产模式（后台运行，不走 watch）

```bash
# ① 先构建
pnpm -r run build

# ② 后台启动 server（日志写文件，不阻塞终端）
cd /Users/lion/workspace/gocode/ai-workbench
nohup node apps/server/dist/main.js > .logs/server.log 2>&1 &
echo $! > .pids/server.pid
```

这种方式需要手动管 PID（`kill $(cat .pids/server.pid)`）、手动看日志（`tail -f .logs/server.log`）。**开发阶段别用这个**，watch 模式改了代码自动重编译省心得多。

### 方式 D：Nest CLI 原始命令（了解一下就行）

```bash
cd apps/server

# watch 模式
npx nest start --watch

# 编译一次再跑
npx nest build && node dist/main.js
```

⚠️ **注意路径坑**：不管从哪里跑 server，**数据库固定从 workspace root 的 `data/workbench.db` 读**（用 `__dirname` 上溯，不依赖 cwd）。所以从 `apps/server/` 目录跑 `nest start --watch` 也能正确定位 db，不会再在 `apps/server/data/` 下意外创建空壳。

## 3. 停止

### 开发模式（前台跑的）

直接在那个终端按 `Ctrl+C`。如果两个在同一个 shell 里并行跑的，一次 Ctrl+C 两个都停。

### 生产模式（后台跑的）

```bash
# ① 按 PID 停
kill $(cat .pids/server.pid)

# ② 如果 PID 文件丢了，按端口找进程
lsof -ti :8700        # 列出占用 8700 的 PID
kill $(lsof -ti :8700)

# ③ 还不掉？强杀
kill -9 $(lsof -ti :8700)
```

### 一键清场（把所有残留的都干掉）

```bash
lsof -ti :8700 :8701 2>/dev/null | xargs kill -9 2>/dev/null
```

## 4. 端口速查

| 端口 | 服务 | 启动命令 | 健康检查 |
|---|---|---|---|
| **8700** | Server（NestJS + Socket.io） | `pnpm --filter @aiwb/server dev` | `curl http://localhost:8700/api/health` |
| **8701** | Web（Vite dev） | `pnpm --filter @aiwb/web dev` | 浏览器 `http://localhost:8701` |
| **6333** | Qdrant（可选，向量库） | 单独启动 Qdrant | `curl http://localhost:6333/collections` |

Web 的 Vite proxy 配置：所有 `/api/*` 和 `/socket.io/*` 请求代理到 `localhost:8700`。所以浏览器只打开 `:8701` 就行，后端全透明。

## 5. 数据文件位置

全部在 **workspace root 的 `data/` 下**：

```
data/
├── workbench.db          ← SQLite 主文件（24 张表）
├── workbench.db-wal      ← WAL 日志（写时产生，正常运行时自动合并）
├── workbench.db-shm      ← WAL 共享内存索引
├── uploads/              ← 知识库原始文件（PDF/TXT/MD 等）
└── qdrant/               ← Qdrant 向量索引文件（如果 qdrant 跑在本地）
```

### 用 sqlite3 CLI 看

```bash
# 进交互终端
sqlite3 data/workbench.db

# 常用命令
.tables                              # 列全部表
.headers on                          # 打开列名
.mode column                         # 对齐输出
SELECT username, role FROM users;    # 查活跃用户
SELECT COUNT(*) FROM models;         # 查模型数量
.exit
```

### 用 DBeaver / Navicat / 其他 GUI 看

新建连接 → SQLite → 文件路径填：

```
/Users/lion/workspace/gocode/ai-workbench/data/workbench.db
```

密码空着就行。

### 清空数据重来

```bash
lsof -ti :8700 | xargs kill -9      # 先停 server
rm -f data/workbench.db*            # 删主文件 + WAL + SHM
pnpm --filter @aiwb/server db:push   # 重建空壳 schema
pnpm --filter @aiwb/server dev       # 再启动，Auth 模块自动补 admin 种子
```

## 6. 日志

### 开发模式（watch）

日志直接打在你跑 `pnpm dev` 的终端里，有 `[Nest]` 前缀。

### 生产模式（后台）

日志文件位置：`.logs/server.log`

```bash
tail -f .logs/server.log       # 实时追踪
tail -n 100 .logs/server.log   # 看最后 100 行
grep -i "error" .logs/server.log
```

### PID 文件位置

`.pids/server.pid`（一个数，就是那个 `node apps/server/dist/main.js` 的进程号）

## 7. 常见问题

### Q: 登录时报 `Unexpected end of JSON input`

**根因**：server 没跑。Vite proxy 转发 `/api/auth/login` 到 `localhost:8700` 连不上，返回空 body，前端 `res.json()` 炸了。

**解决**：开 server → `pnpm --filter @aiwb/server dev`

### Q: 登录/注册用什么账号？

默认 admin 种子（每次 server 启动自动确保存在，幂等）：

| 用户名 | 密码 | 角色 |
|---|---|---|
| `admin` | `admin123` | owner |

可以用环境变量覆盖：

```bash
ADMIN_USER=myadmin ADMIN_PASS=secret pnpm --filter @aiwb/server dev
```

### Q: 新注册的用户是什么角色？

- 第一个注册的 → 自动 owner
- 之后注册的 → member

### Q: 怎么改数据库 schema？

```bash
# 改 apps/server/src/db/schema.ts 之后
pnpm --filter @aiwb/server db:push    # 同步到 db（直接改，不迁移）
```

drizzle-kit 的 `push` 是"原地合并"，小改改够用。复杂改动建议开 migration，但目前还没配。

### Q: 怎么清理重建？

```bash
pnpm -r run build                     # 重新编译 shared + server + web
pnpm -r run build --force             # 或者强制全部重编译
# 或者手动
rm -rf packages/shared/dist apps/server/dist apps/web/dist
```

### Q: db 里看到两套数据？

说明之前有一次用不同 cwd 启动时在 `apps/server/data/` 下意外创建了空壳。检查一下：

```bash
ls data/workbench.db                  # 正确位置
ls apps/server/data/workbench.db      # 幽灵空壳？
```

如果后者存在，直接 `rm -rf apps/server/data`。server 现在用 `__dirname` 固定上溯，不会再在那个位置写了。

### Q: 端口被占用怎么办？

```bash
# 8700 被谁占了？
lsof -ti :8700

# 干掉它
kill $(lsof -ti :8700)
```

### Q: 前端 API 报 401 Unauthorized

两个可能：
1. accessToken 过期 → 自动 refresh，等一下再试
2. refreshToken 也过期了 → 登出重新登录

### Q: Socket.io 连不上？

- 确认 server 在跑（`:8700`）
- 确认 web 页面打开的是 `:8701`（Vite proxy 会把 `/socket.io/*` 转发到 `:8700`）
- DevTools Network 看 `/socket.io/?EIO=4&transport=polling` 是否返回 `200 {"sid":...}`
