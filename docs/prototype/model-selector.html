方案 B
方案 B · 输入框内嵌下拉
下拉嵌入输入框右端与发送键同排。更紧凑，但挤压输入区；移动端软键盘弹出时易误触；原生 select 浮层样式无法定制，终端感打折。

方案 C
方案 C · 斜杠命令切换
输入 / 唤出命令建议后选 /model。极客感最强但零发现性，建议仅作为 A 的补充快捷方式（命令面板机制已存在，组合成本低）。

// 决策参考
· A：不动输入区布局，两处视觉密度一致，浮层可完全终端风定制
· B：省一行空间，代价是移动端拥挤 + 浮层样式不可控
· C：键盘流爽点，配合 A 组合成本不大
· 链路：主页 ↔ 聊天栏共用 store；KB 问答独立（后端 KbAskInput.modelId 需打通，约 3 处小改）
