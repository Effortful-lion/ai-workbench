# 090 · 评论默认折叠 + UI 两级层级

日期：2026-11-09 ｜ 分支：main ｜ 类型：feature

## 一、需求

1. 一级评论不能一上来全展开，固定露出少量，点「展开全部」才铺开；
2. 评论要有层级感，但 UI 只做两级：一级顶格，二级缩进；三级及更深靠「回复 @某人」表达，不再继续缩进。

## 二、为什么两级刚好对上现有模型

后端 `blog_comments` 的 `depth` 只有 0 / 1：任何超过两层的回复都会被压平（`rootId` 指楼层、`parentId` 指楼层、`replyToUsername` 记录真实被回复者）。所以「谁回复谁」的层级信息本来就不在缩进里，而在 `replyToUsername` 上 —— UI 两级不是妥协，是模型本身的投影。

## 三、实现

`CommentThread.tsx`：

| 项 | 值 / 做法 |
|---|---|
| 收起时一级楼层数 | `COLLAPSED_FLOORS = 3` |
| 收起时楼内回复数 | `COLLAPSED_REPLIES = 2` |
| 展开全部 | 按钮「展开全部 N 条评论」（N 用 `commentTotal`，含回复）；若还有未拉取的页，同时触发 `onLoadMore` |
| 楼内展开 | 每个楼层独立「展开其余 N 条回复」，`openReplies[rootId]` 记状态 |
| 二级层级 | 容器 `mt-4 pl-8 border-l border-line/70`：缩进 32 + 1px 结构线 |
| 三级及更深 | 不缩进，靠「回复 @admin」标识（后端已压平，天然同级） |
| 楼层号 | 一级 `#N` 在容器外右侧；二级无楼层号 |

计数标题同时给出两个数：`评论 · 11 / 5 个楼层`，避免「11 条评论只看到 3 条」的再次误读。

## 四、与阅读基线规范的关系

上一轮（089）要求「评论主体对齐正文阅读基线」。一级楼层仍然严格满足（`x=0`，头像外移）；二级按本轮要求缩进 32px，属于**显式例外**：层级信息优先于基线。两条规范冲突时，以最新需求为准。

## 五、验证

真实数据：5 个楼层 / 11 条评论（其中两个楼层各带 3 条回复）。

| 状态 | 结果 |
|---|---|
| 收起 | 渲染 3 个楼层；带回复的楼层只露 2 条 + 「展开其余 1 条回复」；底部「展开全部 11 条评论」 |
| 点展开 | 渲染 5 个楼层，楼内仍各自折叠 |
| 二级视觉 | 缩进 32px + 1px 淡线，与一级拉开层次；三级回复与二级同级，靠「回复 @tester」区分 |

## 六、遗留

- 折叠阈值是常量（3 / 2），若要做成可配，挪到设置项；
- 切换文章时 `expanded` 不会重置（单篇场景无感，多篇连续阅读时会保持展开态）。
