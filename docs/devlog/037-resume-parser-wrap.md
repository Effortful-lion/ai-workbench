# 037 · 简历导入解析：PDF 断行与切碎修复

- 日期：2026-11-04
- 状态：已完成

## 目标

PDF 导入的简历在终端页里排版/语义全乱：长描述被视觉换行切成碎片、词中间被插「；」、技能按括号内顿号切碎、「荣誉奖项」混进技能、职位行丢失。

验收：用户同款 PDF 抽取文本（无 bullet、按视觉行硬换行）解析出完整通顺的经历/技能/项目/教育结构。

## 决策

- **只修规则，不接 LLM**：根因是解析器假设「一行 = 一个逻辑行」，而 unpdf 抽取按视觉行硬换行。用启发式续行合并即可覆盖，成本为零、行为确定；LLM 解析留作后续可选增强。
- **续行合并先于标题判断**：碎片行（如「心集群,以及…」）本身也满足宽松的标题特征，必须先判「上一条没写完」再判「是不是新标题」，否则碎片被提升成新条目。
- **合并要克制**：仅当上一条正文是「宽行（≥20 字符）却无句末标点」或「括号/连接符未收尾」时才拼；「标签：…」或动词（负责/实现/设计…）开头的行视为新一条，防止 bullet 丢失时过度粘连。

## 实现

全部改动集中在 `apps/server/src/resume/resume.parser.ts`：

- **续行合并（`buildEntries`）**：非 bullet、非日期的行，在上一条正文「明显没写完」时用 `smartJoin` 拼回（任一端是 CJK 直拼，否则补空格）；`needsContinuation` 识别尾随 `、，；：/` 与未闭合括号。
- **伪标题拦截**：`职责:/负责/参与/主导` 等标签开头的行永不当条目标题（`LABEL_START_RE`）；含冒号的行不当公司/职位标题；无日期「标题行」只有在上一条已有正文时才开新条目（修「Go开发实习生」被提成条目）。
- **职位/公司回补**：`ROLE_RE` 补「实习生」；头部缺 role/company 时从正文第一行提取。
- **`splitItems` 括号深度感知**：`（）/()/【】/[]` 内的 `、，；` 不再当分隔符；技能项截断 40→60 字符。
- **技能块预合并**：括号/顿号截断的续行先拼回再切分。
- **章节词表**：补 荣誉奖项/获奖/证书/语言/兴趣爱好（归入技能组），不再掉进上一章节当内容。
- **教育**：仅学校名可开新条目（「软件工程 · 相关课程… · 本科」不再单独成条），degree 支持从正文补匹配。

## 验证

- `pnpm --filter @aiwb/server build` 通过。
- 用户同款断行文本（无 bullet）：经历 2 条完整（「场景下消息的实时性」「吞吐量」「资金自动回收」均正确拼合）、技能 6 项完整带括号、项目「配置中心集群」复原、教育单条含 school/major/degree。
- 带 bullet 的规范文本回归：各 bullet 仍为独立条目，无粘连；姓名/意向/技能分组正常。

## 遗留

- bullet 完全丢失且 bullet 间无标点/换行特征时仍可能粘连一条；规则路线无法穷举，必要时再上 LLM 精修。
- 「荣誉奖项」目前并入技能组渲染，档案卡结构无独立奖项字段。
- 扫描版 PDF 依旧走「请粘贴文本」提示，不支持 OCR。
