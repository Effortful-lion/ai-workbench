# 014 · crm 客户管理

- 日期：2026-11-02
- 状态：✅ 完成（接口权限矩阵 / seed 幂等 / 浏览器三角色验证全部 PASS）

## 目标

按总体设计三期第二个模块「客户管理」落地项目客户跟进：

- `~/crm` 终端式客户看板：KPI、客户列表、跟进时间线与命令栏。
- 客户档案：姓名 / 公司 / 联系方式 / 阶段 / 预计金额 / 来源 / 评分 / 备注。
- 跟进记录：线索、通话、会议、邮件、报价、备注六类事件，驱动最近联系时间。
- 超过 14 天未跟进自动标黄，且只对进行中客户生效。
- owner 独占：member / guest 面板 403，服务端权限与 AI Tool 同步过滤。
- 注册 AI Tool：概览、客户列表、待跟进清单、建档、阶段推进、跟进读写与演示数据。
- 本期不做邮件 / 日历自动建档、自动评分与提醒，只做本地客户台账。

## 决策

1. **客户与跟进拆两张表**：`crm_customers` 存档案与阶段，`crm_followups` 存时间线事件；不把跟进记录塞进 `notes`，避免覆盖与无法排序。
2. **`lastContactAt` 由跟进推导**：新增跟进时只有 `happenedAt` 更新才推进最近联系时间，回填历史不会把客户「变新鲜」；删除跟进后回退到剩余最近一条，没有则回到建档时间。
3. **14 天标黄只针对进行中客户**：`won` / `lost` 不参与 stale 计算，避免已成交客户长期无联系被误报。
4. **阶段六态**：`lead → contacted → proposal → negotiation → won / lost`；面板 badge 由「阶段 + 新鲜度」派生（成交在望 / 跟进中 / 待跟进 / 已成交 / 流失），不额外存冗余状态列。
5. **管道金额按进行中客户估值合计**：`pipelineValue` 不含 won / lost，`wonValue` 单独统计已成交合同额；金额按整数元落库，评分 0–100 夹取。
6. **owner-only**：原型 ACL 为 `~/crm owner rw / member × / guest ×`。member 权限列表不授予 `crm:*`，服务端 `PermissionGuard` 与 Tool Registry 按同一套权限过滤。
7. **面板双栏 + 命令栏**：左侧客户行式列表，右侧跟进时间线；所有写操作走命令行（`crm.new` / `crm.log` / `crm.stage`），阶段切换用行内 chips，不引入传统表单卡片。
8. **演示数据幂等**：`crm.seed` 仅在客户表为空时写入 5 位客户与 9 条跟进，重复执行返回 `seeded:false`，不污染真实台账。
9. **前端不直接引用 shared 运行时常量**：shared 以 CJS 产物被 Vite 加载，`CRM_STALE_DAYS` 这类运行时命名导出会触发 `does not provide an export named`；面板内联 `STALE_DAYS = 14` 与服务端常量保持一致，类型仍从 shared 引入。

## 遗留

1. **没有自动建档**：邮件、日历、官网表单不会自动生成客户或跟进；目前只能手工 `crm.new` / `crm.log`。
2. **评分与阶段需人工维护**：`score` 只是档案字段，没有 AI 自动打分或阶段推进建议。
3. **待跟进没有提醒**：14 天标黄只发生在面板内，未接入 012 站内信 / 邮件通知。
4. **与商业化未打通**：客户 `won` 不会联动生成商业订单，`value` 与订单金额没有对账关系。
5. **跟进记录只增删不改**：不支持编辑、附件、@提醒或富文本；删除无二次确认与审计。
6. **没有联系人多条与自定义字段**：每位客户只有一个 `contact` 文本，无多联系人、标签、来源渠道细分。
7. **列表一次性全量加载**：没有分页、虚拟滚动或按项目 / 来源的交叉统计，也没有 CSV 导出。
8. **只有 owner 可访问**：没有「销售只读」或「协作者跟进」等更细角色。
9. **演示数据与真实台账共用表**：无自动清理或标记，删除需逐条操作或手动清库。
