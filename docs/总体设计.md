# AI 工作台 · 总体设计

> 版本：v0.1（讨论稿）  日期：2026-11-02
> 已拍板：NestJS / LangChain.js / 终端极客·暗 / 对话中枢 + 命令面板

---

## 1. 产品定位

**AI-first 的个人工作操作系统**：不是"带 AI 功能的网站"，而是"以 AI 为调度中枢的工作台"。

三条设计原则（贯穿所有模块）：

1. **对话即入口** —— 首页就是一个巨型 AI 对话框，全站 80% 的操作可以从对话/命令发起。
2. **能力即工具** —— 每个业务模块把自己的能力注册为 Tool（查日程、搜知识库、发邮件……），AI 助手统一发现并调用，而不是为 AI 单独写一套逻辑。
3. **权限即边界** —— 用户权限直接映射为 Agent 可用工具的子集。游客连"读"都受限，owner 全权。

---

## 2. 模块分期

| 期 | 模块 | 说明 |
|---|---|---|
| **一期 · 地基** | 用户/权限、首页对话、AI 助手（CLI+Agent）、模型管理、AI 知识库、个人简历、百宝箱 | 工作台的骨架与灵魂 |
| **二期 · 业务** | 项目管理、代码管理、日程管理、邮件管理、站内信 | 成熟 CRUD + 通知体系 |
| **三期 · 商业化** | 商业化管理、客户管理、流水线工厂 | 流水线 = 可视化编排 + 批量跑 Agent，依赖一二期成熟 |

分期理由：一期把"AI 调度中枢"跑通，二三期所有模块自动获得 AI 能力，避免重复建设。

## 3. 交互范式（不传统的核心）

### 3.1 三种界面状态

```
┌─ 状态 A · 对话态（首页） ──────────────────────────┐
│                                                     │
│   ⌘  AI-WORKBENCH                        [guest] ⌄  │
│                                                     │
│                                                     │
│        晚上好，Lion。今天有 3 件事等你处理。          │
│                                                     │
│   ┌───────────────────────────────────────────┐    │
│   │  问我任何事，或输入 / 调用工作台能力…        │ ⌘K │
│   └───────────────────────────────────────────┘    │
│                                                     │
│    [📧 帮我处理今天的邮件] [📅 排一下本周日程]        │
│    [🔍 查知识库里的部署文档] [⚡ 新建 Agent]          │
│                                                     │
└─────────────────────────────────────────────────────┘

┌─ 状态 B · 工作态（对话 + 侧滑面板） ────────────────┐
│                                                     │
│  对话流（窄列，始终在场）   │  模块面板（从右侧滑入）  │
│  ─────────────────────     │  ────────────────────  │
│  你: 打开知识库            │  📚 AI 知识库      [⤢×] │
│  AI: 已打开，共 128 篇文档 │  ┌──────────────────┐  │
│      最近更新《部署手册》   │  │ 🔍 检索 / 对话    │  │
│  你: 搜一下 qdrant 配置    │  │ ▸ 部署手册.md     │  │
│  AI: 找到 3 处，第 2 处最  │  │ ▸ 模型清单.md     │  │
│      相关 ▸                │  │ ...               │  │
│                            │  └──────────────────┘  │
└─────────────────────────────────────────────────────┘

┌─ 状态 C · 沉浸态（CLI 全屏） ───────────────────────┐
│                                                     │
│  workbench@lion:~$ agent run mail-assistant         │
│  ▸ 加载 Agent: mail-assistant (tools: mail.*, llm)  │
│  ▸ 扫描到 12 封未读邮件…                             │
│  ▸ [AI 分类] 重要 3 / 订阅 5 / 垃圾 4                │
│  ▸ 需要我为 3 封重要邮件起草回复吗？ (y/n) _          │
│                                                     │
└─────────────────────────────────────────────────────┘
```

- **状态 A**：首次进入的默认态。招呼语（时间感知 + 待办摘要）+ 巨型输入框 + 动态推荐 chips（由日程/邮件/待办实时生成）。
- **状态 B**：主工作态。模块以**面板**形式从右侧滑入，可堆叠（面包屑式返回）、可⤢全屏。对话列始终在场——任何模块里的内容都能"拖回对话"让 AI 处理。
- **状态 C**：CLI 沉浸态。xterm.js 实现，`/cli` 或命令面板进入，极客主战场。

### 3.2 ⌘K 命令面板（统一调度）

三类命令混排，模糊搜索：

```
⌘K ┌────────────────────────────────────┐
   │ > mail                              │
   ├────────────────────────────────────┤
   │ ▸ 导航   打开邮件管理                │
   │ ▸ 动作   写新邮件 / 同步收件箱        │
   │ ▸ AI    「把今天的重要邮件汇总给我」  │
   └────────────────────────────────────┘
```

命令面板 = 导航器 + 动作触发器 + AI 入口，三者同一 UI。这是"无需手动操作"的物理载体。

## 4. 视觉设计系统

### 4.1 色彩（克制，高级感来源）

| 角色 | 色值 | 用途 |
|---|---|---|
| 底色 · 主 | `#0B0D10` | 页面背景（近黑，带一丝蓝） |
| 底色 · 层 | `#12151A` / `#181C22` | 面板、卡片层级 |
| 边框 · 线 | `#23282F` | 细线框，1px |
| 主点缀 | `#00E59B` | **终端绿**，唯一强调色：光标、焦点、激活态、关键数据 |
| 语义色 | 成功=绿 / 警告=`#FFB000` 琥珀 / 错误=`#FF5F56` | 克制使用 |
| 文本 | `#E6E9EC` 主 / `#8A919A` 次 / `#4A5158` 弱 | 三级灰度 |

> 备选方案：主点缀换琥珀 `#FFB000`（复古 CRT 气质），一键换 token 即可。默认绿。
> 铁律：**一屏之内只有一个强调色**。高级感来自克制，不是来自颜色多。

### 4.2 字体

- **UI 正文/标题：MiSans**（清爽现代，免费商用）
- **代码/数据/终端/数字：JetBrains Mono**（等宽，极客感的主要来源）
- 搭配规则：凡是"系统性内容"（时间、路径、命令、状态、ID）一律等宽体；凡是"人写的内容"一律 MiSans。

### 4.3 材质与细节

- 背景铺**极淡的方格网格**（`1px` 线，透明度 3-4%），像工程图纸。
- 终端/卡片窗口带**标题栏**：左侧 `● ● ●` 三色点 + 等宽体路径标题（如 `~/knowledge/部署手册.md`）。
- 焦点态：`1px` 终端绿描边 + 极轻微外辉光（`box-shadow: 0 0 12px #00E59B22`）。
- 输入光标：方块字符 `▌` 闪烁，不用默认竖线。
- 分隔线用 ASCII 风味：`────── ──────` 或 `// section` 注释式标题。
- 慎用圆角：主圆角 `6px`，终端窗口 `8px`，按钮 `4px`。**不大圆角、不毛玻璃**。

### 4.4 动效原则

- 面板滑入滑出 `200ms ease-out`；命令面板淡入 `120ms`。
- AI 输出：打字机流式 + 光标跟随。
- 加载态：终端式 spinner（`⠋⠙⠹⠸` 字符动画），不用转圈菊花。
- 页面切换无花哨转场，快即高级。

## 5. 技术架构

### 5.1 Monorepo 结构（pnpm workspace）

```
ai-workbench/
├── apps/
│   ├── web/                # React 18 + Vite + Shadcn/ui + Tailwind + Zustand
│   │   └── src/
│   │       ├── components/   # shadcn 基础组件
│   │       ├── features/     # 每个业务模块一个目录（面板+hooks）
│   │       ├── shell/        # 对话中枢、命令面板、CLI、面板管理器
│   │       └── stores/       # zustand
│   ├── server/             # NestJS
│   │   └── src/
│   │       ├── modules/      # 业务模块（auth/resume/toolbox/kb/models/agents/...）
│   │       ├── ai/           # LangChain 运行时、Agent 执行器
│   │       ├── tools/        # ⭐ Tool Registry：模块能力注册中心
│   │       ├── gateway/      # Socket.io WS 网关（流式输出/通知/CLI）
│   │       └── db/           # Drizzle schema + better-sqlite3
│   └── cli-protocol/       # CLI 命令解析协议（可选，先内嵌 server）
├── packages/
│   └── shared/             # 前后端共享：TS 类型、Tool 协议、常量、权限枚举
├── docker-compose.yml      # server + qdrant
└── data/                   # SQLite 单文件 + 上传文件（gitignore）
```

### 5.2 后端关键设计

**Tool Registry（全架构的核心）**

```typescript
// 模块把自己的能力注册为 AI 可调用的工具
@RegisterTool({
  name: 'kb.search',
  description: '检索知识库',
  permission: 'kb:read',          // ← 权限即边界
})
async searchKb(@Ctx() user: User, @Arg('query') q: string) { ... }
```

- NestJS Provider + 装饰器收集所有 Tool，启动时生成 Tool Schema 清单。
- Agent 执行时：根据**当前用户权限**过滤可用工具子集 → 注入 LangChain Agent。
- HTTP API 与 Tool 共用同一 service 层：人调 API，AI 调 Tool，逻辑只有一份。

**其他决策**

| 项 | 选型 | 说明 |
|---|---|---|
| ORM | Drizzle + better-sqlite3 | 轻、快、SQL 亲和，单文件 SQLite 绝配 |
| 认证 | JWT（access 15min + refresh 7d），bcrypt | 角色：`owner` / `member` / `guest`（游客只读且脱敏） |
| 实时 | Socket.io 独立 namespace：`/chat` `/cli` `/notify` | AI 流式、CLI 交互、站内信 |
| LLM 接入 | 自建 provider 适配层（OpenAI 兼容协议为基准） | 模型管理模块统一维护 key/endpoint，全站复用 |
| RAG | LangChain.js + Qdrant 单节点 | 文档切分 → embedding → Qdrant；检索时 namespace 按用户隔离 |
| 邮件发送 | nodemailer（二期） | 日程提醒 + 邮件模块 |

### 5.3 前端关键设计

- **Shell 层**是核心资产：对话中枢、命令面板、面板管理器（Panel Manager：打开/堆叠/全屏/关闭）、CLI 终端。业务模块只实现"面板内容"，不碰导航。
- 状态：Zustand 分 store（`useChatStore` / `usePanelStore` / `useAuthStore`）；服务端数据用 **TanStack Query**，不进 zustand。
- 路由：React Router，但多数"导航"是打开面板而非跳路由——URL 只反映全屏态模块，面板态不进 history（保持对话上下文）。
- WS 客户端封装成 hook：`useStream(channel)` 一行接入流式。

### 5.4 部署

```yaml
# docker-compose.yml
services:
  server:   # NestJS，内嵌托管 web 构建产物（单容器交付）
    build: .
    volumes: [./data:/app/data]
  qdrant:   # 向量库单节点
    image: qdrant/qdrant
    volumes: [./data/qdrant:/qdrant/storage]
```

## 6. 一期模块设计概念（非表单化速览）

| 模块 | 设计概念 |
|---|---|
| **首页** | 招呼语 + 巨型对话框 + 动态 chips（见 3.1 状态 A）。chips 由真实数据驱动：未读邮件数、今日日程、知识库更新 |
| **个人简历** | "终端档案卡"：不是表格式简历，而是一个可滚动的终端窗口——`whoami` 输出基本信息，`ls ./experience` 展开经历时间线，`cat skills.json` 展示技能树。游客访问时是只读的精美页面 |
| **百宝箱** | "快捷指令墙"：工具不是表格行，而是终端命令卡片——每个工具像一条 alias，显示 `▸ name  简介  ↗`，hover 出现使用统计。添加工具走命令面板自然语言："把 https://x 加到百宝箱，归类为设计" |
| **AI 知识库** | 检索即对话：顶部搜索框输入后，AI 直接给答案 + 引用文档列表；文档以终端文件树浏览。上传支持拖文件到对话里 |
| **模型管理** | 模型卡片阵列：每张卡 = 厂商 logo + 模型名（等宽体）+ 状态灯（●可用/●欠费/●未配置）+ 延迟/价格指标。点击卡片在面板内直接对话测试 |
| **AI 助手** | 双模：对话式（首页）+ CLI（xterm.js）。Agent 创建 = 人设 prompt + 勾选工具子集 + 权限上限（不能超过创建者） |

## 7. 数据模型（一期核心表，Drizzle schema）

```
users          id, username, password_hash, role(owner/member/guest), profile_json
sessions       id, user_id, refresh_token, expires_at
conversations  id, user_id, title, agent_id?, created_at
messages       id, conversation_id, role(user/assistant/tool), content, tool_calls_json
agents         id, owner_id, name, persona_prompt, tools_json, created_at
models         id, provider, model_name, endpoint, api_key_enc, status, meta_json
kb_documents   id, owner_id, title, path, mime, status(embedded/pending), created_at
kb_chunks      → Qdrant: { vector, payload: { doc_id, chunk_ix, user_id } }
toolbox_items  id, owner_id, name, url, category, desc, use_count
notifications  id, user_id, type, title, body, read, created_at   -- 站内信
```

## 8. 开放问题（不阻塞设计，开发前确认即可）

1. **点缀色**：默认终端绿 `#00E59B`，备选琥珀 `#FFB000` —— 出第一张效果图时最终确认。
2. **游客权限粒度**：简历/百宝箱公开只读，其余登录可见 —— 是否需要"公开主页"独立路由？
3. **模型 key 存储**：DB 加密存储 vs 环境变量 —— 默认 DB AES 加密（便于模型管理模块自助配置）。
4. **CLI 命令集范围**：一期只做 `agent/kb/model/open` 四类命令，后续随模块扩展。
